**Decision (user, 2026-09-10):** the branch's commit "Replace hand-written
runtime suite with the EITT XML interpreter" (`3a5e2d4a` pre-rebase) went too
far. The interpreter replaces only the tests whose requirement the official
template covers. Everything else the hand-written suite tested — and upstream
`work_in_progress` kept adding to it, 176 → 349 tests in 20 files by
2026-09-10 (CoAP option/payload hardening, SWU state-machine edge cases,
observe, stricter AT validation, ...) — must survive.

**Layout (current, after the 2026-09-14 separation).**

| Tier | What | Where |
| --- | --- | --- |
| unit | Google Test, untouched by this work | `tests/unit/` |
| fuzz | libFuzzer harnesses over the pre-auth parsers, clang only, no DUT | `tests/fuzz/` (`fuzz_*.c`, seeds generated by `make_corpus.py`) |
| common | shared infrastructure, NO tests | `tests/common/` (`fixtures.py`, `transport/`, `tools/`, `runtime_test_server.c`, `requirements.txt`) |
| eitt | template-driven interpreter, one pytest item per TestCase | `tests/eitt/test_eitt.py`, with `interpreter/`, `gui/`, `data/` beside it |
| harness | tests of the interpreter and GUI code itself, no DUT | `tests/eitt/harness_tests/` (`test_events.py`, `test_comment_scheme.py`, `test_project_copy.py`, `test_gui_*.py`) |
| runtime | hand-written tests for behaviour the template does NOT cover | `tests/runtime/` — 19 behaviour-named `test_*.py` and nothing else |

```
tests/
  pytest.ini    pythonpath = . common eitt ; testpaths = eitt runtime
  conftest.py   thin: re-exports everything common/fixtures.py defines
  common/  fixtures.py transport/ tools/ runtime_test_server.c requirements.txt
  eitt/    test_eitt.py interpreter/ gui/ data/ harness_tests/
  runtime/ the 19 test modules
  unit/  fuzz/
```

A hand-written test is dropped only when a template TestCase exercises the
same requirement, and the drop records the EITT case id so it is traceable.

- **Separated into `tests/eitt` + `tests/runtime` + `tests/common` on
  2026-09-14**, one commit "Separate the eitt and runtime test tiers; shared
  infrastructure in tests/common". The 2026-09-11 split had put the three
  tiers in subdirectories of `tests/runtime/` while the shared code stayed at
  the `tests/runtime/` level; now the two device tiers are siblings under
  `tests/` and the shared code is its own package. Everything moved with
  `git mv`; no test logic changed. Points worth remembering:
  - The interpreter package was **renamed `eitt` -> `interpreter`**: a package
    named `eitt` living inside a directory named `eitt` that is itself on
    `sys.path` would shadow itself. Every `from eitt.X import` became
    `from interpreter.X import`, including one dynamic
    `__import__("eitt.events", ...)` in `test_gui_window.py` that a
    regex over import statements does not catch — **grep for the module name
    as a STRING too**, not just as an import.
  - `conftest.py` became **`tests/common/fixtures.py` + a thin
    `tests/conftest.py`**. pytest reads fixtures and hooks only from a file
    called `conftest.py`, but a conftest is not importable by a stable module
    name from a sibling directory, and the tiers need both: `from fixtures
    import DUT_IA, set_lsm`. So the definitions live in the importable module
    and `tests/conftest.py` does `from fixtures import *` plus an explicit
    `from fixtures import pytest_addoption, pytest_collection_modifyitems`.
    **A new `pytest_*` hook in fixtures.py must also be named in that explicit
    import**, or it silently stops being a hook.
  - `tests/pytest.ini` carries `pythonpath = . common eitt` (paths relative to
    the ini file) and `testpaths = eitt runtime`. `testpaths` only applies
    when pytest is given no path argument, so `run-in-docker.ps1 -Tier all`
    names both directories explicitly rather than relying on it.
  - Only `test_eitt.py` changed `__file__` depth (`data/` became a sibling,
    not a parent's child). `interpreter/`, `gui/` and `harness_tests/` are all
    still exactly two levels above `data/`, and `fixtures.py`'s
    `parents[2]` still lands on the repo root. Verified cwd-independent by
    running the harness tier from `D:\`.

**Why:** the interpreter's purpose is to stop hand-porting each EITT template
revision, not to lose device coverage that KNX never wrote a TestCase for.

**How to apply:**

- Never delete a hand-written test without naming the EITT case that covers it.
- Before adding a hand-written test, check the template for a covering
  TestCase; if one exists, do not add the test.
- Port in file-sized, reviewable commits; keep upstream's test bodies, change
  imports/fixtures only, and run the ported file in Docker before the next.
- Rebase first, restructure second (done in that order on 2026-09-10 for a
  reason: 107 upstream commits changed device behaviour both tiers depend on).
- Coding is delegated to Opus subagents; the orchestrating session reviews.
- `git rebase` autostash silently swallowed the untracked
  `docs/proposal-resource-caps.md` once; check untracked files after any
  rebase in this repo.
